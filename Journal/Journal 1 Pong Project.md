9/21/2026

	Today was the first day of working on revamping the basic Pong game. Deciding how to revamp Pong was a very enriching experience, as it forced me to question how certain modifications can change the game and if they would ultimately change the main objective of the game. After pondering for some time, I decided to alter the following: make the ball's speed increase every time it hits a paddle (both player and CPU), make an additional ball spawn after a certain amount of paddle hits, and have the game end once all balls exit the field. In coming up with these changes, it shifts the game goal from "score X amount of points to win" to "maintain ball momentum with the CPU to prevent a mutual loss", which brings about a cooperative element to an otherwise single-player game experience.

	Applying said wanted modifications brought about some difficulty for me, as I am not familiar with the C# coding language enough to know how to alter the code to fit the new needs I desire. As a result, I consulted various YouTube videos and various Unity and coding question threads to assist me in applying said modifications.

	The first and easiest change I implemented was removing the scoreboard, as there was no need for it since there is no score to keep track of. To do that I just deselected the scoreboard in the hierarchy to remove it from the game scene. Following that, when it came to increasing the ball's speed, I added the float value speedIncrease and set it to 5.0f. Following that, I added the private void function of OnCollisionEnter2D(Collision2D collision) allowing me to check if the ball interacted with a paddle and if it did to increase its speed by 5 by using speed += speedIncrease; and AddStartingForce();. When it came to spawning another ball, I had to follow a similar approach to adding two new values of private int paddleHits = 0; and public int hitsPerSpawn = 4;. These would later be used in the two new void functions, public void RegisterPaddleHit(), which checked and recorded every time a ball interacted with a paddle, and private void SpawnNewBall(), which would spawn a new ball after the spawned balls interacted with the paddle four times. While testing these changes, it made me realize that implementing a mechanic in code is a lot more intuitive than how I imagined it working conceptually. For instance, I originally thought that increasing the ball's speed would make the game progressively more difficult, but more factors became affected, such as the paddles and the natural rhythm of the game. By increasing the game's difficulty, it inherently affects the playability of the game, which was something I realized and took into consideration when modifying it. As a result, I naturally encountered some issues along the way such as spawning additional balls and keeping track of them, showing me that a seemingly small change in one aspect of the game can affect multiple parts of the existing game.

	All in all, this process was quite challenging for me as I am not familiar with the terms and language yet for C#, making it difficult to think about how to approach tackling the changes let alone doing them. While I did manage to implement many alterations that I wanted, I wouldn't consider the prototype to be finished yet as I can go back and refine the code while reflecting on some cosmetic and thematic changes to be done. Design ideas differ from concept to creation, which hit me only after I attempted to implement the changes I had wanted.
